# Inbox 문서 작성

Inbox 기록은 작업의 진행·검토·인계에 필요한 **근거와 미해결 사항**을 남긴다. 정본 문서나 작업 상태의 대체물이 아니다.

## 작성 기준

- 먼저 동일 작업의 기존 기록을 찾아 갱신한다. 질문, 책임 또는 근거가 구분될 때만 문서를 추가한다.
- 작업 범위와 기준 시점(ref, revision, 날짜 등)이 판단에 중요하면 명시한다.
- 확인한 사실, 해석·권고, 미검증 사항을 구분한다. 실행하지 않은 테스트나 확인하지 않은 현재 상태를 완료로 표시하지
  않는다.
- 후속 작업이 있으면 다음 행동, 필요한 근거, 차단 사항을 재개할 수 있도록 기록한다.
- 지속해서 필요한 결론은 실제 책임을 가진 deck, 코드 또는 repository 문서에 반영한다. Inbox를 정책·교육과정의 정본으로
  승격하지 않는다.
- `.inbox/README.md` 외의 임시 기록을 `.inbox/` 밖의 파일에서 직접 참조하지 않는다.
- Git 기록에 남겨도 안전한 내용만 작성한다. 비밀, credential, 개인 대화 또는 재배포 제한 원문을 기록하지 않는다.

## 템플릿 선택

필요할 때만 해당 양식을 참고한다. 섹션은 작업의 질문에 맞게 수정하고 사용하지 않는 placeholder는 제거한다.
**모든 문서에 동일한 형식이나 frontmatter를 강제하지 않는다.**

| 필요한 기록 | 선택적 템플릿 |
| --- | --- |
| 질문·근거·불확실성을 조사 | [Research](../templates/research.md) |
| 실행 범위와 완료 조건을 정리 | [Plan](../templates/plan.md) |
| 변경이나 결과를 근거로 검토 | [Review](../templates/review.md) |
| 다른 세션·작업자에게 이어주기 | [Handoff](../templates/handoff.md) |

문서의 배치가 불명확하면 [조직 가이드](organization.md)를, 작성 후 정리 여부를 판단할 때는
[라이프사이클](lifecycle.md)을 읽는다.
