# 작업 기록의 보존·정리

**문서 리뷰, 정본 반영, PR merge·close만으로 작업 종료를 추론하지 않는다.**

## 삭제 조건

일반적인 삭제 전에 다음을 모두 확인한다.

1. **실제 작업이 종료**됐으며 남은 과제·차단·인계 필요성이 없다.
2. 지속적으로 필요한 결론은 정본에 반영됐거나 반영할 내용이 없다.
3. 생성 또는 마지막 **실질적 갱신** 후 최소 7일이 지났다.
4. 필요한 근거를 정본·코드·PR·검증 기록·Git history에서 다시 확인할 수 있다.

종료·날짜·보존 필요성이 불확실하면 유지한다. 이동, 개명, PR merge 또는 사소한 metadata 수정은 보호 기간을 갱신하지 않는다.

## 예외와 경계

- 완료된 자료는 **삭제 우선**이다. 원문이 재현·감사에 필요하고 Git 이력만으로 복구하기 어려운 경우에만 아카이브를 검토한다.
- 진행 중인 작업 기록은 오래되거나 PR이 닫혀도 보존한다.
- 디렉터리 수 제한과 자동 삭제는 두지 않는다. 사용자가 별도 정리를 요청하면 대상·영향을 확인하고 처리한다.
- `.inbox/README.md`와 `.configs/`의 안내·템플릿은 작업 기록 정리 대상이 아니다.
