# Inbox 자료의 라이프사이클

Inbox 기록은 작업을 진행하는 동안 만들고 수정·검토·인계한다. **정본 반영, 문서 리뷰 또는 PR merge·close만으로 실제 작업이 종료된 것은 아니다.**

## 정리 판단

작업 자료의 일반적인 삭제는 다음 조건을 모두 확인한 뒤 수행한다.

1. 관련 작업이 실제로 종료됐고, 계속할 과제·차단 사항·인계 필요가 없다.
2. 지속적으로 필요한 결론이 책임 있는 정본에 반영되었거나 추가 반영할 내용이 없다.
3. 생성 또는 마지막 **실질적 갱신**으로부터 최소 7일이 지났다.
4. 삭제 후에도 필요한 근거를 정본·코드·PR·검증 기록·Git history에서 다시 확인할 수 있다.

조건이나 날짜를 확인할 수 없으면 삭제하지 않고 보존 여부를 다시 검토한다. 경로 이동, 이름 변경, PR merge, 사소한 metadata 수정만으로 7일 보호 기간이 새로 시작하지 않는다.

## 보존 원칙

- 완료된 작업은 **삭제 우선**이다. 원문이 꼭 필요하고 Git 기록만으로 복구·재현하기 어려울 때만 예외적으로 아카이브를 검토한다.
- **진행 중이거나 재개해야 하는 작업**은 날짜가 오래되거나 PR이 닫혀도 유지한다.
- 날짜 디렉터리 개수 제한이나 일괄 자동 삭제를 두지 않는다.
- 사용자가 범위와 목적을 명시해 별도 정리를 요청했다면 대상과 영향을 검토하고 그 요청에 맞게 처리한다.
- `.configs/`의 가이드·템플릿 및 `.inbox/README.md`는 작업 기록이 아니므로 위 정리 대상에 포함하지 않는다.

장기적으로 필요한 결론을 반영할 때는 원래 정본의 권한·책임을 따르고, 임시 기록을 자동으로 작업 지침으로 취급하지 않는다.
