# Inbox 배치와 구성

작업 자료는 **같은 작업을 다시 찾고 이어갈 수 있는 단위**로 묶는다. 새 문서를 만들기 전에 해당 작업의 기존 기록을
확인하고 재사용한다.

## 디렉터리 선택 순서

아래 우선순위를 적용한다.

| 우선순위 | 작업 식별자 | 경로 |
| --- | --- | --- |
| 1 | GitHub Issue 또는 PR 번호 | `.inbox/github-<number>/` |
| 2 | GitHub 번호가 없는 Branch | `.inbox/branch-<slug>/` |
| 3 | 위 식별자가 없는 작업의 시작 날짜 | `.inbox/YYYY-MM-DD/` |

- 번호는 **현재 자료가 지원하는 주된 작업**의 Issue/PR 번호를 사용한다. 단순히 언급된 다른 PR 번호로 분류하지 않는다.
- 주된 작업을 하나로 특정할 수 없다면 임의로 번호를 선택하지 않는다. 명확한 Branch가 있으면 Branch를, 없으면 날짜를
  사용한다.
- 날짜는 작업 디렉터리를 처음 만든 날이다. 이후 문서 갱신 날짜로 디렉터리 이름을 바꾸지 않는다.
- 작업 중 Branch가 PR로 바뀌더라도 기존 디렉터리를 자동으로 이동하지 않는다. 이동할 실제 이점이 있을 때만 링크·참조를
  확인하고 변경한다.

## 파일과 문서 묶음

- 작은 작업은 한 문서로 시작한다. 조사, 계획, 검토 또는 인계를 별도로 재사용해야 할 때만 문서를 추가한다.
- 파일명은 `research-<topic>.md`, `review-<topic>.md`처럼 역할과 주제가 드러나도록 정한다. 번호 부여와 metadata는 필수가
  아니다.
- 여러 문서를 탐색할 진입점이 필요할 때만 작업 디렉터리에 `README.md`를 두고 각 문서의 역할을 짧게 연결한다.
- 이미 존재하는 날짜 기반 기록과 기존 파일명은 그대로 유지한다. 새 규칙 적용만을 위한 일괄 이동·개명은 하지 않는다.

예시:

```text
.inbox/
├── github-35/
│   ├── research-posix-shell.md
│   └── review-curriculum.md
├── branch-experiment-tracing/
│   └── notes.md
└── 2026-11-22/
    └── research-topic.md
```

문서 내용을 만들거나 갱신할 때는 [작성 가이드](writing.md)를, 삭제·보존 판단에는 [라이프사이클](lifecycle.md)을
참고한다.
