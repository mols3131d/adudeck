# 작업 단위와 경로

새 문서를 만들기 전에 **같은 작업의 기존 디렉터리와 기록**을 확인한다.

## 선택 우선순위

| 순서 | 작업 식별자 | 경로 |
| --- | --- | --- |
| 1 | GitHub Issue·PR 번호 | `.inbox/github-<number>/` |
| 2 | GitHub 번호가 없는 Branch | `.inbox/branch-<slug>/` |
| 3 | 별도 식별자 없음 | `.inbox/YYYY-MM-DD/` |

- 단순히 언급된 번호가 아니라 **자료가 지원하는 주된 작업**의 번호를 쓴다. 주된 번호가 불명확하면 임의 선택하지 않고
  Branch 또는 날짜를 사용한다.
- 날짜는 디렉터리를 **처음 생성한 날**이며 문서 갱신일로 바꾸지 않는다.
- Branch가 PR로 바뀌어도 기존 경로를 자동 변경하지 않는다. 이동이 필요할 때만 관련 링크·참조를 확인한다.

## 문서 번호와 번들

작업 디렉터리의 **독립 문서와 번들 디렉터리**는 같은 순서를 사용한다.

- 문서: `<NN>-<slug>.md` 또는 `<NN>-<type>-<slug>.md`
- 번들 디렉터리: `<NN>-<slug>/` 또는 `<NN>-<type>-<slug>/`
- `NN`은 `00`부터 시작하는 두 자리 번호다. 같은 위치의 독립 문서와 번들 디렉터리 사이에서 번호를 중복하지 않는다.
- 번호는 기본 읽기 순서를 나타낸다. 새 항목은 기존 최대 번호 다음에 배치하고, 수정·삭제 후에도 기존 번호를 재배열하지 않는다.
- `slug`는 짧고 구별 가능한 kebab-case이며, `type`은 `research`, `plan`, `review`, `handoff`처럼 필요할 때만 쓴다.

**번들**은 관련 문서를 하나의 주제로 묶는 디렉터리다. 번들에는 진입점 `README.md`를 두고 문서 선택 링크만 간결하게
작성한다. 번들 내부 문서에도 **해당 번들에서 별도로 `00`부터** 번호를 부여한다. 번들 안에 번들을 중첩하지 않는다.
[번들 README 템플릿](../templates/bundle-readme.md)은 필요할 때만 사용한다.

```text
.inbox/github-45/
├── 00-research-topic.md
├── 01-review-topic/
│   ├── README.md
│   ├── 00-findings.md
│   └── 01-evidence.md
└── 02-handoff-topic.md
```

작은 작업은 단일 문서로 시작한다. 여러 독립 기록을 탐색해야 할 때만 작업 디렉터리에 선택적 `README.md`를 둔다.
`README.md` 및 `.configs/`의 재사용 지침·템플릿은 번호 대상이 아니다. 기존 무번호 파일은 일괄 개명하지 않으며,
실제 이동·개명 시 관련 링크를 확인한다.
