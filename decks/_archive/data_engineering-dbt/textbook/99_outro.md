# 99. 마무리 및 회고

길었던 dbt 기초 튜토리얼 프로젝트를 모두 완주하신 것을 축하합니다!
이제 여러분은 단순한 SQL 작성을 넘어, 원천 데이터를 가공하고 테스트하며 문서화하는 현대적인 데이터 파이프라인(Analytics Engineering)의 핵심을 직접 경험했습니다.

## 최종 파이프라인 검증

모든 작업을 마쳤으므로, 최종 빌드를 실행하여 프로젝트 전체가 완벽하게 동작하는지 확인해 봅시다.

```bash
uv run dbt build
```

(`dbt build`는 `run`, `test`, `seed` 등을 여러분이 구성한 의존성 그래프(DAG) 순서에 맞게 한 번에 실행해주는 가장 강력한 명령어입니다. 이 명령어가 에러 없이 성공한다면 목표 달성입니다!)

## 회고 질문 (Retrospective)

진짜 학습은 스스로 질문에 답할 수 있을 때 완성됩니다. 아래 질문들에 답해보며 지난 튜토리얼 과정을 복기해 보세요.

- 이 튜토리얼에서 만든 최종 산출물은 무엇인가요?
- `fct_orders`는 어떤 분석 질문에 답하기 위해 생성된 마트 모델인가요?
- dbt는 ETL(Extract, Load, Transform) 중 정확히 어느 영역을 담당하나요?
- model 파일 작성 시 materialization(`view` vs `table`)을 구분하는 기준은 무엇인가요?
- `ref()` 함수는 단순히 SQL 테이블명을 치환해주는 것 외에 가장 중요한 어떤 역할을 하나요?
- data test가 '통과(Pass)'한다는 것은 쿼리 관점에서 정확히 무슨 뜻인가요?
- 데이터 모델링을 할 때 굳이 staging 계층과 marts 계층을 분리하는 핵심 이유는 무엇인가요?
